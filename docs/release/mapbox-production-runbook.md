## Release decision and non-negotiable scope

Mapbox is **an optional, user-opened reference-area viewer** in native booking, not a home geocoder, Xooter tracker, live ETA or coverage guarantee. The approved website homepage retains its visually approved South Africa/Gauteng SVG and does not fetch Mapbox tiles. Do **not** swap it for the old main-branch Mapbox GL JS component, or declare the web illustration proof of a working map API.

Native `@rnmapbox/maps` powers five public suburban reference pins (Sandton, Bryanston, Rosebank, Fourways, Midrand). The customer opens it on booking **Your home / office** after entering an address, and can close it without losing their form. The entire Mapbox layer receives **zero** entered address, access instructions, customer ID, live coordinates or geocode input. Coverage and available Xooters are confirmed only by the booking flow/backend, not by a marker.

Production builds now fail configuration preflight without `EXPO_PUBLIC_MAPBOX_PUBLIC_TOKEN` of public `pk.*` shape. Builds with a malformed/secret `EXPO_PUBLIC_` map token fail before release. Production EAS profile cannot use `development`/preview app environment by accident. Preview/development deliberately allow a missing token for testing non-map workflows. Client token shape is **not** proof it is legitimate or permitted to call Mapbox; successful native tile rendering is a separate device gate.

4. Confirm Mapbox's dashboard shows successful authorised native style/tile usage on actual builds, not merely token present. ## Acceptance evidence required, on BOTH iOS and Android

- Log in to a consenting, non-production test account; go to Book → Step 2 **Your home / office**; **View neighbourhood map** must open the native map and render five pins. Mapbox logo and attribution control remain visible, unobscured and functional. Scrolling and closing the map cannot destroy the typed booking form.

Verify Mapbox attribution telemetry/privacy options work on both platforms; have privacy/legal review of SDK telemetry and map data-sharing, under POPIA.

- Native user-address geocoding, house pins, real worker GPS, driving route and accurate ETA are **separate future product features**, and must not be claimed as delivered by the reference-area map. Any live worker location would require explicit opt-in, job-scoped ownership/RLS, expiration, status-aware cadence, location permission, server enforcement and independent privacy review.
