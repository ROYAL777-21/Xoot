### SEC-2 — `/book` is publicly cacheable and indexable on the live site — **Medium** — live site

**Evidence**

```console
$ curl -s -D - -o /dev/null 'https://xoot.co.za/book?cb=12961'
HTTP/2 200
cache-control: public, max-age=0, must-revalidate     # ← expected: no-store, private
age: 340919                                           # ← ~4-day-old public edge-cache object
x-vercel-cache: HIT
# (no X-Robots-Tag header)                            # ← expected: noindex, noarchive, nosnippet

# working counter-examples on the same deploy:
$ curl -sI https://xoot.co.za/app | grep -iE 'cache-control|x-robots-tag'
cache-control: no-store, private, max-age=0, must-revalidate
x-robots-tag: noindex, noarchive, nosnippet
```

**Why it matters.** `/book` is the transactional booking entry. The repo contract
(`vercel.json` since `ca1cdc6`, 2026-10-24; asserted by `live-header-contract.test.mjs:85`)
requires `noindex` + `no-store` so booking URLs (which can carry query state) never land in
shared caches or search engines. Live, a ~4-day-old `/book` response is being served from a
public edge cache with no noindex — a crawler or shared-cache middlebox can retain it.

**Fix.**
1. Redeploy (see SEC-1) — the `/book` header rules are already in `vercel.json:34-46`.
2. After redeploy, verify the edge cache is purged (Vercel purges on new deployment; if any
   `age:` > 0 remains on `/book`, raise a cache invalidation).
3. Add `/book` to the post-deploy verification gate so this can't silently regress again.

### SEC-3 — SPA catch-all returns HTTP 200 for every unknown path (soft 404s) — **Medium** — live site

**Evidence**

```console
$ for p in /.env /.git/config /.DS_Store /server-status /phpmyadmin /admin /wp-login.php /api/ /ops/; \
    do curl -s -o /dev/null -w '%{http_code}  '$p'\n' https://xoot.co.za$p; done
200  /.env
200  /.git/config
200  /.DS_Store
200  /server-status
200  /phpmyadmin
200  /admin
200  /wp-login.php
200  /api/
200  /ops/

$ curl -s https://xoot.co.za/.env | head -c 120
<!doctype html><html lang="en">…  # ← SPA shell, not real data (no leak today)
```

**Why it matters.** `vercel.json:27-30` rewrites `/((?!\.well-known/).*)` → `/_spa.html`,
so **every** non-`well-known` path answers 200 with the app shell. (a) Attack scanners and
your own monitoring cannot distinguish probe traffic from real traffic — every probe
"succeeds"; (b) if a sensitive file (`.env`, `.git/`, a future export) ever lands in a build
output it will be served, and nothing in the status code will flag it; (c) soft-404s waste
crawl budget and pollute analytics.

**Fix.** In `vercel.json`, keep dot-leading paths out of the SPA fallback so they get a real
404 (path-to-regexp negative lookahead, same style as the existing `well-known` exclusion):

```json
{ "source": "/((?!\\.well-known/)(?!\\.).*)", "destination": "/_spa.html" }
```

Mirror in `public/.htaccess` (before the SPA `RewriteRule`):

```apache
RewriteCond %{REQUEST_URI} !^/\.well-known/
RewriteCond %{REQUEST_URI} !^/\.
```

Optionally also 404 an explicit junk list (`/phpmyadmin`, `/wp-login.php`, `/server-status`).
Re-run the probe loop above: dotfile paths must return 404.

### SEC-10 — Minor header hygiene: `www` HSTS weaker, obsolete XSS header, host banners — **Low** — live site

**Evidence**

```console
$ curl -sI https://www.xoot.co.za | grep -i strict-transport
strict-transport-security: max-age=63072000        # ← no includeSubDomains, no preload
$ curl -sI https://xoot.co.za | grep -iE 'x-xss-protection|^server|x-vercel-id'
x-xss-protection: 1; mode=block                    # ← obsolete (OWASP: remove or 0)
server: Vercel
x-vercel-id: hkg1::…
```

**Why it matters.** The `www` 307 redirect carries a weaker HSTS policy than the apex
(`max-age=31536000; includeSubDomains; preload`); a client that only ever touches `www`
never gets the preload pin. `X-XSS-Protection: 1; mode=block` is deprecated and can itself
introduce bugs in legacy browsers. `Server`/`x-vercel-id` are platform-injected (can't be
removed on Vercel) — informational only.

**Fix.** Add `"Strict-Transport-Security": "max-age=31536000; includeSubDomains; preload"`
to the `www` host (or fold `www` into the same header block in `vercel.json`). Remove
`X-XSS-Protection` (SEC-7).

## Part 2 — Repo findings

### SEC-5 — Hostinger `.htaccess` has drifted from the Vercel contract — **Medium** — repo

**Evidence** (`public/.htaccess`, shipped by `scripts/build/copy-hostinger-files.mjs`)

```apache
# line 11 — CSP ends with:
… frame-ancestors 'none'; form-action 'self'; upgrade-insecure-requests"
#   ^ no https://sandbox.payfast.co.za/eng/process, no https://www.payfast.co.za/eng/process
#     (vercel.json:59 and public/_headers:2 both include them)

# lines 21-24 — noindex/no-store env regexes:
SetEnvIf Request_URI "^/(app|auth|admin)(/|$)" XOOT_NOINDEX=1
SetEnvIf Request_URI "^/xooter(/|$)" XOOT_NOINDEX=1
#   ^ /book is missing entirely (vercel.json has had /book rules since ca1cdc6, 2026-10-24)

# no `Options -Indexes` anywhere in the file
```

**Why it matters.** The same `dist/` is published to Vercel **and** copied to Hostinger
(`copy-hostinger-files.mjs`). On Hostinger: (a) PayFast checkout POSTs are blocked by CSP
`form-action 'self'` (availability + a tempting "quick fix" of weakening CSP under
pressure); (b) `/book` gets neither noindex nor no-store — the SEC-2 defect but permanent on
that host; (c) without `Options -Indexes`, any directory that ever loses its index file
becomes listable on Apache.

**Fix.** In `public/.htaccess`:
1. Line 11: replace `form-action 'self'` with
   `form-action 'self' https://sandbox.payfast.co.za/eng/process https://www.payfast.co.za/eng/process`.
2. Add `/book` to both `SetEnvIf` regexes:
   `SetEnvIf Request_URI "^/(app|auth|admin|book)(/|$)" XOOT_NOINDEX=1` (+ the `XOOT_NOSTORE` twin).
3. Add `Options -Indexes` at the top of the file.
4. Add the dotfile fallback exclusions from SEC-3.
Then extend `scripts/security/assert-static-hosting-security.mjs` to diff the three header
sources (vercel.json / `_headers` / `.htaccess`) so they can't drift apart again.

### SEC-6 — Netlify `public/_headers` is missing the `/book` private-route blocks — **Low** — repo

**Evidence** (`public/_headers:46-76`): blocks exist for `/app`, `/auth`, `/admin`, `/xooter`,
`/xooter/*` — **no `/book` or `/book/*`**, while `vercel.json:34-46` has both.

**Why it matters.** The declared private-route contract (hardening doc §"Private routes")
is `/app`, `/auth`, `/admin`, `/xooter`, `/book`. Whichever host serves the site, the
protection set must be identical; today a Netlify deployment would expose `/book` publicly
cacheable (the exact SEC-2 condition).

**Fix.** Append to `public/_headers`:

```
/book
  X-Robots-Tag: noindex, noarchive, nosnippet
  Cache-Control: no-store, private, max-age=0, must-revalidate

/book/*
  X-Robots-Tag: noindex, noarchive, nosnippet
  Cache-Control: no-store, private, max-age=0, must-revalidate
```

### SEC-7 — Obsolete `X-XSS-Protection: 1; mode=block` still configured — **Low** — repo (ships live)

**Evidence:** `vercel.json:74-75`, `public/_headers:6`, `vite.config.ts:64` (dev server).
Live response shows `x-xss-protection: 1; mode=block` (see SEC-10 evidence).

**Why it matters.** The header is deprecated (browsers ignore or can be harmed by it);
OWASP recommends removing it or sending `0`. It also scores as a flag on every security
scanner the founder's daily testing will run, creating noise.

**Fix.** Delete the `X-XSS-Protection` entries from `vercel.json`, `public/_headers`
(and optionally `vite.config.ts` dev headers). `.htaccess` already omits it — good.

### SEC-8 — CSP `style-src 'unsafe-inline'` — **Low** (hardening backlog) — repo + live

**Evidence:** `vercel.json:59`, `public/_headers:2`, `public/.htaccess:11` —
`style-src 'self' 'unsafe-inline'` (script-src is strict `'self'`, no unsafe-eval ✓).

**Why it matters.** `unsafe-inline` in `style-src` means any future HTML-injection bug can
be escalated to CSS-based exfiltration/UI redressing. Everything else about this CSP is
strict, so this is the one remaining relaxation. It is **not** a quick fix: the app uses
React inline `style` attributes, which require `unsafe-inline` unless converted to hashes
or moved to classes/`<style>` with nonces.

**Fix (staged).** (1) Grep for `style={{` usage and migrate high-risk components to CSS
classes; (2) once inline styles are gone, tighten to `style-src 'self'`; keep as a tracked
backlog item, not a blocker. Record the decision in the hardening doc so it isn't re-found
daily.

### SEC-9 — `concierge-config`: unauthenticated and unthrottled DB-backed endpoint — **Low** — repo

**Evidence:** `supabase/functions/concierge-config/index.ts:22-26` documents "Read-only, so
there is no rate limit … a `select` on a table of at most a few dozen rows"; config.toml
sets `verify_jwt = false`. Contrast: `public-xooter-directory/index.ts` received exactly
this treatment — an IP-keyed `consumeRateLimit` (30/5 min) — on 2026-10-28 *because direct
scripted calls bypass HTTP caches* and hit the DB on every request. `concierge-config`'s
60-second `Cache-Control: public` cache is equally bypassable with `curl` in a loop.

**Why it matters.** Every anonymous GET runs a service-role DB query — an unthrottled
cost/DoS lever on the shared Supabase project, and the one public function without any
limiter. Low severity because the query is tiny, it fails closed, and the endpoint is
slated for deprecation — but the inconsistency is worth closing while it exists.

**Fix.** Mirror the directory pattern in `concierge-config/index.ts` (IP-keyed,
e.g. 30 reads / 5 min, no `Cache-Control` on the 429), or accelerate the planned
deprecation. If left as-is, record the accepted-risk rationale in the hardening doc so it
isn't re-found.
