# Zoot Secrets Inventory

Reviewed: 2026-06-29

This is the master credentials inventory for Zoot. It lists what must exist, where it belongs, and what still needs manual setup. It must not contain real secret values.

Status values:

- `Referenced` - code already reads the value.
- `Template` - template/docs prepared, implementation or provider setup pending.
- `Dashboard` - configured in third-party dashboard, not stored in repo.
- `Manual` - requires founder/operator setup.

## Security Rules

- `VITE_` variables are public only.
- `EXPO_PUBLIC_` variables are public only.
- No service-role keys in frontend code.
- No API secrets in frontend code.
- No real `.env` files are committed.
- Staging and production credentials must be separate.
- Production must fail loudly if required public config is missing or preview-like.
- Webhooks must verify signatures or shared secrets where supported.
- Payment success must never be trusted from the frontend.
- OTP codes must be provider-generated by Supabase Auth or Twilio Verify, never hardcoded in frontend code.
- Any Twilio, Supabase, payment, OpenAI, Brevo, KIE, Airtable, Hostinger, Cloudflare, Mapbox, App Store, or Google Play secret pasted into chat must be rotated before production and stored only in its provider dashboard, Supabase Edge Function secrets, EAS secrets, CI secrets, or an approved vault.
- Zoot does not have a registered production domain yet. Treat `zoothome.co.za` and `staging.zoothome.co.za` as intended placeholders until registration, DNS, TLS, OAuth, sender-domain, app-link, and store URL verification are complete.
